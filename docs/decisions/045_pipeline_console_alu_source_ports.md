# ADR 045: Pipeline console - the ALU source mux inputs were left unconnected

**Status:** Accepted
**Date:** 2026-10-21
**Related:** ADR 005 (ALU operand-A source extended to 2 bits), ADR 044 (step
mode), `docs/vga_console_review.md`

---

## Context

The hardware stage of the thesis campaign (`make thesis-hardware`) failed on
the fourth consecutive flash of the pipeline architecture.  Quartus did not
report a design error; it aborted the synthesis stage with an internal error:

```
Info (286030): Timing-Driven Synthesis is running
Internal Error: Sub-system: SCL, File: /quartus/synth/scl/scl_state_syn.cpp, Line: 895
node_id != 0
Stack Trace:
    0x24508: SCL_SYN_STATE::set_blame_reg_for_fanouts + 0x1e8 (SYNTH_SCL)
    0x28854: SCL_SYN_STATE::write_removed_registers_report + 0x1004 (SYNTH_SCL)
    0x27792: SCL_SYN_STATE::write_optimized_node_reports + 0x5b2 (SYNTH_SCL)
```

The crash is inside the report of the registers that synthesis removed, while
it attributes their fanouts to the registers that replace them.  The abort is
not deterministic: the same sources compiled without error on the next run and
on eight consecutive runs of the four-program hardware loop.

Two warnings preceded it:

```
Warning (12241): 1 hierarchies have connectivity warnings
Warning (13024): Output pins are stuck at VCC or GND
    Warning (13410): Pin "vga_sync_n" is stuck at GND
```

### Cause

The synthesis report names the nodes involved:

```
; screen_writer_pipeline:u_writer|snap_alua_src[0]  ; Stuck at GND due to stuck port data_in ;
; screen_writer_pipeline:u_writer|snap_alua_src[1]  ; Merged with screen_writer_pipeline:u_writer|snap_alub_src[0] ;
```

The console writer takes `alua_src` and `alub_src` as inputs and snapshots
them into `snap_alua_src` / `snap_alub_src` at the end of a sweep.  The
pipeline top level did not connect those two ports, so the synthesis mapped
them to GND:

* `snap_alua_src[0]` became a constant, so synthesis removed the register.
* `snap_alua_src[1]` and `snap_alub_src[0]` were both constant, so synthesis
  merged them into a single register.

A register that is removed while being merged with another one leaves the
fanout accounting of `write_removed_registers_report` with a node that no
longer exists, which is the `node_id != 0` assertion.  The report is the
first place where the synthesis state machine walks the removed registers, so
the abort happens there and not in the logic itself.

The single-cycle design never showed the defect: `top_single_cycle.sv`
connects both ports.  The pipeline top level missed them when the writer was
regenerated by the colour rework (commit `36f14e2`), which regenerated
`rtl/pipeline/screen_writer_pipeline.sv` with the two new ports but did not
touch `rtl/pipeline/top_pipeline.sv`.

## Decision

The pipeline top level connects the two ports to the EX stage signals, which
are the ones the rest of the console already reads (`alu_a`, `alu_b`, `alu_op`
come from the same stage):

```systemverilog
.alua_src         (ex_alua_src),
.alub_src         (ex_alub_src),
```

The `ALUASrc` and `ALUBSrc` fields of the console now show the value the ALU
operand mux actually selected, instead of a constant zero.

## Consequences

* The synthesis no longer produces a constant register that is removed and
  merged with another one, so the report that crashed no longer has to
  account for it.  The connectivity warning (12241) disappears with it.
* The number of synthesis warnings for the pipeline drops from 59 to 58.
* The console shows the real ALU operand source of the instruction in flight.
  Before the fix the field was frozen at zero, which is a wrong value and not
  a missing one.
* The single-cycle design is unchanged; it already connected both ports.
