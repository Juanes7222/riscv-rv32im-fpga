# ADR 055 - VGA console: architecture and interface changes on both tops

**Status:** Accepted (records a feature that already exists in the RTL)
**Date:** 2026-11-12
**Depends on:** ADR 004 (shared module boundary), ADR 023 (`wr_en_gated`),
ADR 042 (counters frozen in the console), ADR 044 (step mode),
ADR 047 (data window), ADR 054 (program loader)

---

## Context

The board shows the internal state of the processor on a 720p monitor: register
file, ALU operands and result, PC, the decoded control signals, the data-memory
window and the two measurement counters. The feature grew over several weeks
(`vga_*`, `video_memory`, `screen_writer_*`, the memory shadows, a second PLL,
`dbg_regs` and `dbg_wr_*`), and it changed the interface of modules that ADR 004
declared frozen: `register_file` gained `dbg_regs`, and the data memory gained a
debug write-beat. There is a descriptive document
(`docs/vga_console_review.md`, `docs/visualization_module.md`) but no ADR, so
this ADR records the architecture and, explicitly, the interface changes.

## Decision

### Display chain

| Stage | Module | Notes |
|---|---|---|
| Pixel clock | `rtl/shared/vga_pll.sv` | ALTPLL 50 MHz → 74.25 MHz (297/200); the simulation branch approximates it with a divider |
| Sync generation | `rtl/shared/vga_controller.sv` | 1280 × 720 @ 60 Hz, 1650 × 750 total |
| Character memory | `rtl/shared/video_memory.sv` | 160 × 45 cells of 16 bits, synchronous read, M10K |
| Glyph output | `rtl/shared/vga_text_mode.sv` | font ROM + 16-colour palette, RGB registered at the pins |
| Content | `rtl/{single_cycle,pipeline}/screen_writer_*.sv` | **generated** by `scripts/gen_screen_writer.py` from `synthesis/*/fields.json` and `screen.mif` |

The console has its own clock domain. The processor keeps its own PLL
(`cpu_pll.sv` for the single-cycle, 50 MHz for the pipeline) and the only
crossing is through the shadows below.

### Memory shadows (the interface changes ADR 004 did not foresee)

The VGA side cannot read the processor memories directly: they belong to the
processor clock domain and to its single read port. Two shadows duplicate what
the console needs:

- `rtl/shared/vga_rom_shadow.sv` mirrors the instruction memory. Its write port
  is the **program loader** (`loader_imem_wr_en`), so a runtime load is visible
  on the screen (ADR 054).
- `rtl/shared/vga_mem_shadow.sv` mirrors the data-memory window, byte-lane by
  byte-lane. It is written with the CPU store (`dm_wr`, `alu_sum`,
  `dmem_dbg_wr_be/data`); the pipeline additionally muxes the loader into it.

Both are dual-clock: write on the processor clock, read on the pixel clock. A
word written while the console is drawing it may appear one frame late; that is
accepted. The console is a debug view, not an architectural state.

### Register-file interface change

`rtl/shared/register_file.sv` exposes the whole array as a flat 1024-bit vector:

```systemverilog
output logic [1023:0] dbg_regs   // {x31, x30, ..., x1} — read-only debug view
```

This is the change ADR 004 forbade without a new ADR. It is read-only and has no
synthesis cost beyond the routing to the console (the array already exists), but
it does enlarge the sensitive fan-out of every register. The console reads it on
the pixel clock, so the value is a snapshot, not a coherent frame.

### Measurement fields

The panel shows `cycle_count`, `instr_retired`, `cycles_at_done`,
`instr_at_done` (ADR 042) plus the derived CPI. Those fields are generated by
`scripts/add_console_measure_fields.py`, which patches `fields.json` and the
`screen.mif` layout; the values themselves are frozen when `tohost` is written,
so the panel keeps showing the final measurement after the program ends.

### Freeze interaction

A console that changes a thousand times per second cannot be read. The panel is
readable because `SW[9]` freezes the processor (ADR 044); the counters, the
register file and the PC stop together. The console keeps refreshing at 60 Hz.

## Consequences

- The console is a first-class consumer of the processor state: any change to
  the memory read port, the register file or the counters must be checked
  against the shadows and `fields.json`.
- `screen_writer_*.sv` are **generated files**. Editing them by hand is lost on
  the next `make screen`; the source of truth is `scripts/gen_screen_writer.py`
  plus `synthesis/*/fields.json`.
- Two PLLs run in the design (processor and pixel). The Fmax figures of ADR 049
  and 050 are for the processor clock; the VGA path is timed separately
  (`docs/vga_fmax_isolation.md`).
- The data-memory shadow in the single-cycle does not follow the loader, so a
  loaded data word appears only after the program stores to it. Cosmetic, and
  documented in ADR 054.
- The full defect history (torn digits, `X` fields, off-screen content) and the
  fixes are in `docs/vga_console_review.md`; this ADR does not repeat them.
