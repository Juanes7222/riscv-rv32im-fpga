# ADR 025 - Memory Initialization: `.mem` Path Injection via `` `define `` Preprocessor Macro

**Status:** Accepted (updated 2026-11-12 to match the implemented header)
**Date:** 2026-05-04
**Supersedes:** `parameter string MEM_FILE` approach attempted during early RTL development.
**Depends on:** ADR 013 (memory depths), ADR 014 (`.mem` format and generation pipeline)

## Context

`instruction_memory.sv` and `data_memory.sv` (single-cycle) plus
`instruction_memory_pipe.sv` and `data_memory_pipe.sv` (pipeline) all need a
mechanism to inject the path of their initialization files into `$readmemh` at
elaboration time. The `.mem` file format and the ELF-to-`.mem` conversion
pipeline are fully defined in ADR 014 and are not reconsidered here. This ADR
exclusively addresses how those paths reach the RTL without hardcoding them in
the module bodies.

## Decision

Memory file paths are specified via preprocessor macros defined in the header
`rtl/shared/mem_config.vh`. Every memory module includes it and uses the macros
directly in `$readmemh`.

The header is **committed to version control**: it is not in `.gitignore` and
there is no `.template` file. The committed version carries the default build
paths and guards them so a tool can override them:

```verilog
// Generated by scripts/gen_mem_config.py - do not edit manually
//
// The `ifndef guards let a simulator override the paths from the command
// line (-DIMEM_FILE=...), so the simulation and the synthesis build can load
// different memory images without fighting over this file.
`ifndef MEM_CONFIG_VH
`define MEM_CONFIG_VH

`ifndef IMEM_FILE
`define IMEM_FILE "../../build/imem.mem"
`endif

`ifndef DMEM_FILE
`define DMEM_FILE "../../build/dmem.mem"
`endif

`endif
```

The nested `` `ifndef IMEM_FILE `` / `` `ifndef DMEM_FILE `` guards are the key
mechanism: a tool can pass `-DIMEM_FILE=...` or `-DDMEM_FILE=...` and win over
the committed defaults without touching the file. That is how the simulation
Makefiles and the synthesis flow share one header while loading different
images. There is no template to copy and no manual edit step:
`scripts/gen_mem_config.py` rewrites the defaults for the loaded program, and
the guards let individual runs override them.

`make mem ELF=...` (and every `make build` / `make sim` target that depends on
it) regenerates the header. Paths inside it are resolved against the consuming
tool's working directory, so `gen_mem_config.py --relative-to` computes the
needed relative path explicitly (the Makefile passes the synthesis directory).

## Normative Specification

### Header: `rtl/shared/mem_config.vh` (committed, regenerated by the build)

See the block above; `scripts/gen_mem_config.py` writes exactly those guards.

### Generator: `scripts/gen_mem_config.py`

```bash
python3 scripts/gen_mem_config.py \
    --imem        <absolute path to imem.mem> \
    --dmem        <absolute path to dmem.mem> \
    --relative-to <directory the path should be relative to> \
    --validate-linux-path <imem.mem>
```

The script validates that the `.mem` files exist and normalizes Windows paths to
Linux paths for Quartus on the DE1-SoC host.

### Usage in the memory modules

Every memory includes the header with a relative path and guards the read:

```systemverilog
// rtl/single_cycle/instruction_memory.sv
`include "../shared/mem_config.vh"
...
initial begin
    `ifdef IMEM_FILE
        $readmemh(`IMEM_FILE, mem);
    `endif
end
```

`data_memory.sv` (single-cycle) and `data_memory_pipe.sv` (pipeline) follow the
same pattern with `DMEM_FILE`; `rtl/shared/vga_mem_shadow.sv` and
`rtl/shared/vga_rom_shadow.sv` also read `DMEM_FILE` to build the console
image. If a macro is absent the memory is left at its power-up value (zero in
both Icarus and Quartus).

### Tool integration

- **Icarus / cocotb:** the sources use relative `` `include `` paths, so no extra
  include directory is needed. Per-run overrides go through
  `COMPILE_ARGS += -DIMEM_FILE=...`.
- **Quartus:** the synthesis `setup.tcl` adds `rtl/shared` to the project search
  path; the projects are scripted, so no `.qsf` line is required.

## `.mem` File Format

The `.mem` files consumed by `$readmemh` conform to ADR 014: one 32-bit word per
line in hexadecimal with no `0x` prefix and no address markers, little-endian
byte order, padded with `00000013` (NOP: `ADDI x0, x0, 0`) to the full depth when
the program is shorter than the memory. `.mem` files are produced by
`scripts/elf_to_mem_split.py` from the ELF; this ADR does not redefine that
pipeline.

## Consequences

- One committed header, regenerated by the build. No `.template` file exists and
  none is planned: the `` `ifndef `` guards replace it.
- Changing the benchmark requires only re-running the `.mem` generation and
  `gen_mem_config.py`; no RTL file is edited.
- Synthesis replicas (ADR 024, Anteproyecto §7.1.3) use the same header for all
  five runs of a benchmark, so every replica loads identical program content.
- Both Icarus and Quartus use the same include mechanism, eliminating the risk of
  loading different binaries in simulation and synthesis.
- The committed header appears as modified in `git status` after a build that
  points at a different `.mem`; that is expected and should not be committed
  unless the default program changes.
- `IMEM_DEPTH` and `DMEM_DEPTH` remain module parameters (ADR 013, ADR 047) and
  are not affected by this mechanism.
